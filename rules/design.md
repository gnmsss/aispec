# 设计规范(跨域:视觉、交互、无障碍、响应式)

适用:所有含 UI 的域(frontend、桌面、移动端)。设计产出与 UI 编码均须遵守。

## 审美方向(设计前必做)

1. 先理解产品上下文(用户、场景、调性),再从审美方向中**明确选定一种**并贯彻:极简克制 / 丰富表现 / 专业严谨 / 温暖亲和 / 高端精致 / 活力潮流 / 复古怀旧 / 未来科技 / 编辑杂志 / 粗野主义 / 有机自然 / 装饰艺术。
2. 回答「这个设计让人记住的一个点是什么」——独特配色、意外布局、精心微交互、独特字体组合任选其一做差异化。
3. 大胆的极简与精致的极繁都是好设计,关键是意图明确;禁止无意识收敛到「居中卡片堆叠 + 蓝紫渐变」的 AI 通用脸。

## 字体排印(MUST)

1. 展示字体与正文字体配对;避免 Arial/Inter/Roboto/Open Sans 等无个性默认字体。中文推荐:展示用思源宋体/方正标雅宋/汉仪旗黑,正文用思源黑体/苹方/HarmonyOS Sans;英文推荐:展示 Playfair Display/Fraunces/Sora,正文 DM Sans/Plus Jakarta Sans。
2. 标题至少 3 级视觉层级;正文 ≥ 14px(移动端 ≥ 16px);行高 1.4–1.6(中文偏 1.6);正文行宽 ≤ 70 字符(中文约 35 字)。

## 色彩与主题(MUST)

1. 完整配色体系用 token/CSS 变量承诺一致性;1–2 个主导色 + 1 个锐利强调色,优于平均分配多色;禁止「紫色渐变白底」等 AI 万能配色。
2. 浅色背景不用纯白(用 `#FAFAFA` 类微色调白),深色背景不用纯黑(用 `#0A0A0A`–`#1A1A1A`);双主题下配色均和谐。
3. 满足 WCAG AA 对比度(见无障碍节);背景可用渐变网格/噪点/几何图案等技法营造氛围,不默认纯色。

## 布局与动效(SHOULD)

1. 拥抱非对称、有意重叠、对角线视线引导;避免全部居中卡片、等宽等高网格、无焦点均匀分布。
2. 动效服务功能:页面加载交错入场、滚动渐显、悬停反馈、状态平滑过渡、数字过渡;时长 150–300ms 交互 / 300–600ms 入场,缓动用 ease-out 系。

## 设计 Token 与组件(MUST)

1. Token 分类:颜色(语义化:`color-primary`、`color-surface`、`color-danger`)、字号、间距(4/8 基数)、圆角、阴影、断点;命名语义化,禁止页面硬编码裸值。
2. 组件状态完整:默认/悬停/按下/聚焦/禁用/加载全部定义;常用组件 2–3 个尺寸变体。
3. 必备组件:按钮、输入、选择、表格、卡片、标签、徽章、Toast、弹窗、抽屉、空状态、骨架屏、导航(顶部/侧边/底部标签)。

## 交互原则(MUST)

1. 一致性:相同操作相同交互模式;可见性:系统状态始终可感知(loading、进度、结果)。
2. 容错:破坏性操作二次确认或可撤销;表单错误就地提示原因与解法;及时反馈:操作后 100ms 内有响应,>1s 显示 loading,>3s 显示进度。
3. 表单:标签清晰、必填标注、错误就地、提交防重复;列表:分页/无限滚动明确、空态设计、批量操作确认。
4. 弹窗克制:优先就地展开与抽屉;嵌套弹窗禁止超过 2 层。

## 无障碍(MUST,AA 级)

1. 对比度:正文 ≥ 4.5:1,大文本与 UI 组件 ≥ 3:1;颜色不是唯一信息手段(色 + 图标 + 文字);链接除颜色外有下划线等区分。
2. 触控目标 ≥ 44×44px,相邻间距 ≥ 8px(视觉小的用 padding 扩展);Android/Flutter 按平台标准 ≥ 48dp。
3. 键盘可访问:Tab 聚焦全覆盖、焦点环可见、弹窗焦点陷阱、ESC 关闭、Enter/Space 激活。
4. 文本可缩放 200% 不破坏功能;功能性图片有 alt/contentDescription,装饰图 `alt=""`。
5. 动效安全:尊重 `prefers-reduced-motion`;禁止每秒闪烁 3 次以上的内容。

## 响应式(MUST)

1. 移动优先,内容驱动断点;常用 3 断点即可,token 化:sm(<768)/md(768–1023)/xl(≥1440) 为最小集,完整集 xs/sm/md/lg/xl/2xl。
2. 导航适配:桌面侧边/顶部完整导航 → 平板折叠图标 → 手机底部标签(3–5 核心)+ 汉堡;内容:桌面多列 → 手机单列纵向堆叠。
3. 图片按 DPR 与断点提供多规格;字号随断点微调,禁止桌面字号直接搬移动端。
