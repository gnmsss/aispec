# 前后端协作与 API 契约(跨域)

适用:所有涉及前后端接口、鉴权、联调、发布协同的需求。数据库冲突以 `rules/database.md` 为准;端内实现细节以各域规则为准。

## 协作原则(MUST)

1. 先契约后开发:接口契约(路径、方法、字段、错误码、鉴权、幂等)确认后再并行开发。
2. 先兼容后替换:线上字段与行为变更走兼容窗口,不得直接破坏旧调用方。
3. 先验证后发布:联调通过 + 回归通过后再灰度发布。

## API 契约(MUST)

1. 契约必须包含:请求参数、响应结构、错误码、鉴权方式、幂等要求、请求/响应/错误示例。
2. 枚举值由服务端单一定义,前端仅消费;客户端必须容忍未知枚举值(忽略或 fallback)。
3. 新增字段默认可选 + 向后兼容且有默认值;删除字段必须先完成使用方清理。
4. 时间字段明确时区与格式(ISO 8601 或时间戳,统一 UTC)。

## 版本管理(MUST)

1. 主版本进 URL(`/api/v1`),仅不兼容变更时递增;兼容变更不改 URL 版本,可经响应头 `X-API-Version` 标识。
2. 不兼容变更(删字段、语义变更、鉴权变更)必须评审并出迁移计划:影响面、迁移步骤、回滚方案、完成时间。
3. 废弃流程:文档 + 响应头(`Deprecation`/`Sunset`)公告 → 过渡期(公开 API ≥ 6 个月,内部 ≥ 3 个月)→ 调用量 < 1% 后申请下线;同时活跃主版本 ≤ 2 个;废弃字段标记 `deprecated` 保留至少 2 个版本。
4. 大版本迁移必须附迁移指南:变更摘要、不兼容清单、时间线、客户端迁移步骤。

## 错误码体系(MUST)

1. 错误码格式 `{域前缀}_{语义}`(如 `USER_NOT_FOUND`、`ORDER_AMOUNT_INVALID`),可读、稳定、服务内唯一;禁止纯数字码。
2. 业务错误与系统错误区分,禁止同一语义;HTTP 状态码语义化映射(400 校验 / 401 认证 / 403 授权 / 404 / 409 冲突 / 5xx 系统)。
3. 服务端统一错误码定义与文档;客户端维护错误码 → 本地化文案映射表,未识别错误码显示通用文案 + 错误码。
4. 高风险操作失败必须给出可操作提示(重试/联系支持/回退动作)。

## 联调与测试(MUST)

1. 联调前完成契约自测:请求示例、响应示例、错误示例可跑通。
2. 联调至少覆盖:成功路径、鉴权失败、参数错误、幂等重试。
3. 提测前:前端 `lint + typecheck + test` 通过,服务端质量门禁通过。

## 发布与回滚(MUST)

1. 接口变更需求采用灰度发布;顺序默认「先服务端兼容发布,再前端切换」。
2. 回滚可执行:服务端可回滚版本,前端可回退开关或版本;发布记录含变更内容与回滚步骤。

## 观测协同(SHOULD)

1. 前后端一致的 `trace_id`/`request_id` 透传;核心接口监控成功率、耗时、错误码分布。
2. 线上排查顺序:契约 → 网络 → 服务端日志 → 前端映射。
