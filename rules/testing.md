# 测试规范(跨域:E2E 与性能测试)

适用:所有域。域内单元/集成测试细则见各域 practices;本文件覆盖跨域 E2E 与性能测试基线。

## 测试策略(MUST)

1. 测试金字塔:单元测试(多、快)→ 集成测试(中)→ E2E(少而准);E2E 只覆盖高价值关键路径,不追求全场景。
2. 核心链路必须有 E2E:登录认证、核心业务主流程(如下单/支付)、权限边界。
3. 修复的线上缺陷若属核心链路,补 E2E 回归用例。

## E2E 测试(MUST)

1. 框架:Web 用 Playwright(默认);移动端用 Maestro/Appium 按平台选型统一。
2. Page Object Model:每页面/组件一个 PO 类,封装定位与操作;用例只调 PO 方法,断言在用例层;命名 `{page}.page.ts`、`{feature}.spec.ts`、`{scope}.fixture.ts`。
3. 用例:describe 按模块分组;标题「动词 + 预期结果」;用例相互独立,不依赖执行顺序。
4. 测试数据:fixture 或 API 预创建,测试后清理;禁止硬编码生产数据;测试账号前缀 `test_e2e_`。
5. 等待:禁止固定 sleep/`waitForTimeout`,用条件等待(`waitForSelector`/`waitForResponse`);默认超时 30s 按场景调整。
6. CI:独立测试环境;失败自动截图/录像;报告自动上传(HTML/JUnit);冒烟 ≤ 10 分钟,全量 ≤ 30 分钟;冒烟不过阻断发布。

## 性能测试(MUST)

1. 核心 API 与关键业务流程必须定义性能基线(P95/P99 延迟、QPS、错误率、资源水位);上线前至少一轮基线测试;重大变更后回归。
2. 工具统一选型:k6(默认)/wrk/vegeta;脚本入库,参数(并发、时长、目标)可配置。
3. 测试类型按需覆盖:基准(单接口)、负载(预期峰值)、压力(找极限)、浸泡(长时稳定性)。
4. 通过标准明确:如 P95 ≤ 基线 × 1.2 且错误率 < 0.1%;劣化超阈值阻断发布并限时优化。
5. 性能测试环境尽量镜像生产配置;结果记录留档,趋势可对比。

## 测试报告(MUST)

E2E 与性能测试报告统一包含:环境、日期、用例/场景总数与通过率、失败详情(原因 + 截图/数据)、结论(冒烟通过与否、可发布性判定:可以发布 / 修复后发布 / 不建议发布)。
