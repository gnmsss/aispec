# UI/UX 设计与走查

两种模式:**设计模式**(产出设计方案)与**走查模式**(审查实现还原度)。设计约束统一以 `rules/design.md` 为准。有 Pencil MCP 时用其创建 .pen 可视化原型(先调 `get_guidelines`);无 MCP 时退化为文本化设计方案 + CSS 变量。

## 设计模式(四阶段)

### Phase 1:设计调研

理解产品上下文(用户、场景、调性);按 `rules/design.md`「审美方向」选定一种并说明差异化记忆点;竞品参考(风格/布局/配色/交互)。
产出:设计方向说明(方向、品牌色、差异化点)。

### Phase 2:交互设计(UX)

信息架构(页面层级、导航结构)→ 核心用户流程 → 完整页面清单与跳转关系 → 全局交互规则(加载/空态/错误/成功反馈,遵循 design.md「交互原则」)→ 响应式策略(断点与导航适配)。
产出:信息架构图、用户流程、页面清单。

### Phase 3:视觉设计(UI)

1. 定义设计 Token(色彩、字体、间距、圆角、阴影、动效时长),遵循 design.md 的字体排印与色彩规则;导出 CSS 变量格式供前端直接使用。
2. 组件设计:状态完整(默认/悬停/按下/聚焦/禁用/加载),必备组件清单见 design.md。
3. 逐页面设计,浅/深双主题验证。

产出:设计 Token(CSS 变量)、组件规格、页面设计(.pen 或文本规格)。

### Phase 4:设计验证

检查完整性(页面全覆盖)、一致性(Token 使用统一,无硬编码值)、无障碍(AA 对比度、触控目标、键盘可达,见 design.md「无障碍」)。
产出:验证结论与待修项。

## 走查模式

对比设计基准(设计稿/Token 定义)与实际实现(截图或代码):

1. **视觉一致性**:颜色/字体/间距/圆角与 Token 一致,无硬编码偏差;双主题正常。
2. **交互完整性**:所有状态实现(loading/空态/错误/禁用);反馈及时;破坏性操作有确认。
3. **响应式**:断点行为符合设计;移动端触控目标达标。
4. **无障碍**:AA 对比度、alt/语义标签、键盘可达、reduced-motion 尊重。

每项标注:通过 / 不通过(附位置 + 修复建议)/ 不适用。
产出:走查报告 + 还原度评分(A 完全还原 / B 轻微偏差 / C 明显偏差 / D 未按设计实现)+ 修复清单(按严重度排序)。
