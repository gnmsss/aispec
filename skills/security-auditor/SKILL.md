# 安全审计工具

以 `rules/security.md` 为基线对项目做系统性安全审计。审计只输出发现与建议,不修改代码;MUST 级条款违规为 P0 阻断项,SHOULD 级为 P1 改进项。

## 工作流

### 1. 确定范围

从任务提取审计目标(全项目 / 特定模块 / PR 变更);识别技术栈,涉及域的安全细则读对应 `rules/<域>/baseline.md` 安全节;范围不明确时向用户确认。

### 2. 必查项(任何审计都执行)

1. **密钥泄露检测**:扫描源码与配置中的硬编码密钥/Token/密码/连接串;检查 `.env` 是否入库、lockfile 是否忽略。
2. **依赖安全**:检查 lockfile 与漏洞扫描配置(govulncheck / dotnet list --vulnerable / pip-audit / pnpm audit / cargo audit 按栈);高危(CVSS ≥ 7.0)必须列出。

### 3. OWASP Top 10 逐项检查(适用项)

注入(SQL 拼接/命令注入)、失效认证(Token 策略、密码哈希)、敏感数据泄露(明文存储/传输、日志)、不安全设计(缺少限流/防重放)、安全配置错误(CORS \*、调试端口、默认凭据、缺安全响应头)、失效访问控制(越权、租户隔离)、XSS(未消毒输出)、不安全反序列化、已知漏洞组件、日志与监控不足(审计日志缺失)。

### 4. 威胁建模(新项目或重大架构变更时)

STRIDE 六类逐项过:仿冒、篡改、抵赖、信息泄露、拒绝服务、权限提升;识别攻击面,每个威胁给缓解措施。

### 5. 输出报告

结构:审计概览(范围、技术栈、结论分级)→ 发现清单(每条:严重度 P0/P1/P2、位置 `file:line`、问题描述、修复方案)→ 依赖扫描结果 → 密钥检测结果 → 威胁建模(如执行)→ 整体结论(可上线 / 修复 P0 后上线 / 不建议上线)。

## 跨域联动

- 数据库安全问题(备份、脱敏、权限)→ 结论中引用 `rules/database.md`
- API 契约安全(错误信息泄露、版本)→ 引用 `rules/collaboration.md`
- 客户端存储安全 → 引用对应客户端域 baseline
